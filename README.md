## 📖 Overview

This repository provides an enterprise-grade collection of **AI Agent Skills** compatible with **Google Antigravity (AGY)**, **Gemini CLI**, **Claude Code**, **Cursor**, **Windsurf**, and **Codex**.

Unlike conventional coding agents that operate on naive "happy-path" assumptions and superficial code slicing, these skills enforce:
* **Lead SRE-grade rigor & Inversion Thinking** ("Destroy weak thinking before it becomes code").
* **Ground-Truth AST Knowledge-Graph Verification** (`CBM` + `CRG`).
* **Multi-Round Adversarial Verification** (Sequential fresh-eyes subagent swarms).
* **Full-Lifecycle Autonomous Product Building** (From raw idea to complete code).
* **Design System Intelligence** (UI/UX Pro Max with 79 styles & 192 palettes).
* **Extreme YAGNI & Simplicity** (Ponytail suite & Elon Musk 5-step pruning).
* **Zero-Server Infrastructure & Cloud Safety** (Offline-first sync & ephemeral disk protection).

## 🌟 Detailed Guide: Har Skill Ka Purpose & Use-Cases

---

### 1. 📐 Autonomous Planning & Hardening Suite

#### `anti-fragile-think` — Inversion Systems Thinking & Multi-Order Reasoning
* **Directory:** [`skills/anti-fragile-think/`](./skills/anti-fragile-think/SKILL.md)
* **Trigger:** `/think`, `/anti-fragile-think`, `/reason`
* **Purpose:** System Reliability Engineer (SRE) perspective se kisi bhi new concept ya architecture ko deeply evaluate karna.
* **Use Cases:**
  1. *1-Year Post-Mortem Simulation:* Maan lo 12 mahine baad project crash ho chuka hai — uska exact root cause kya tha?
  2. *Multi-Order Chains ("And Then What?"):* 1st-order solution (e.g. cache lagana) ke 2nd-order (polling flood) aur 3rd-order (cache stampede/crash) consequences dekhna.
  3. *Chesterton's Fence:* Purane legacy code ke historical reasons samjhe bina use delete ya modify hone se rokna.

#### `anti-fragile-planning` — Pre-Mortem First Implementation Planner
* **Directory:** [`skills/anti-fragile-planning/`](./skills/anti-fragile-planning/SKILL.md)
* **Trigger:** `/implement`, `/plan`
* **Purpose:** New features ya changes ka SRE-grade, step-by-step engineering plan banana.
* **Use Cases:**
  1. *AST-Grounded Scope:* CBM se caller trees aur CRG se blast radius verify karke plan banana (Zero guesswork).
  2. *5 Chaos Vectors Defense:* Network drops, user cancellation, malformed JSON, process leaks, aur race conditions ko pehle se design karna.
  3. *Invariants & Rollbacks:* Har implementation step ke sath headless verification aur instant rollback mechanism design karna.

#### `anti-fragile-audit` & `audit` — Forensic Architectural Audit
* **Directory:** [`skills/anti-fragile-audit/`](./skills/anti-fragile-audit/SKILL.md) | Alias: [`skills/audit/`](./skills/audit/SKILL.md)
* **Trigger:** `/audit`, `/anti-fragile-audit`
* **Purpose:** Existing plan, RFC, PR diff ya architecture ko build karne se pehle ruthlessly stress-test karna.
* **Use Cases:**
  1. *Destroy Weak Thinking:* Plan ko praise karne ke bajaye uske hidden failure modes aur bottlenecks ko expose karna.
  2. *Technically Correct vs. Practically Toxic:* Check karna ki plan unit tests pass karte hue bhi real-world me fail kyu hoga.
  3. *Phantom Symbol Busting:* Plan me likhe hue files/functions ko physical disk aur AST graph se cross-verify karna.

#### `auto-hardened-plan` — Autonomous End-to-End Planning & Self-Hardening Pipeline
* **Directory:** [`skills/auto-hardened-plan/`](./skills/auto-hardened-plan/SKILL.md)
* **Trigger:** `/auto-hardened-plan`, `/auto-harden`
* **Purpose:** Ek hi command me requirements se lekar 5-round battle-hardened plan banana.
* **Use Cases:**
  1. *Autonomous Multi-Round Loop:* Draft v1.0 banana ➔ 5 sequential fresh-eyes Flash subagents spawn karke plan par attack karwana ➔ har flaw ka concrete code fix physical file me patch karna.
  2. *Zero Defect Convergence:* Loop tabhi rukta hai jab at least 4-5 rounds complete ho chuke hon aur 0 critical flaws bache hon.

#### `multi-phase-audit` — Autonomous 5-Round Fresh-Eyes Forensic Audit Swarm
* **Directory:** [`skills/multi-phase-audit/`](./skills/multi-phase-audit/SKILL.md)
* **Trigger:** `/multi-phase-audit`, `/deep-audit`
* **Purpose:** Existing plan ya existing codebase par 5 sequential independent subagents se forensic audit karwana.
* **Use Cases:**
  - Round 1: Core Architectural & Inversion Flaws
  - Round 2: Temporal Drift, State Races & Concurrency
  - Round 3: User Chaos, Network Instability & Leaks
  - Round 4: Anti-Overengineering & Simplicity Pruning
  - Round 5: Verification & Zero-Defect Convergence

#### `orchestrated-hardened-plan` — Master Monolithic Hardening × Decomposed Execution DAG
* **Directory:** [`skills/orchestrated-hardened-plan/`](./skills/orchestrated-hardened-plan/SKILL.md)
* **Trigger:** `/orchestrate`, `/orchestrated-plan`, `orchestrated-hardened-plan`
* **Purpose:** *"Plan as One, Execute as Many"* — Complex multi-layer systems (DB + Worker + UI) ke liye single monolithic plan ko intelligent dependency graph (DAG) me baantkar context-safe execute karwana.
* **Use Cases:**
  1. *Context Window Exhaustion Prevention:* 3000-line ka single plan kisi ek AI agent ko dene par agent cognitive overload se critical edge cases miss kar deta hai. Yeh skill plan ko atomic, independent chunks me divide karti hai.
  2. *DAG Dependency Engine:* Har chunk ke exact prerequisites, input/output contracts, aur verification gates define karti hai taaki subagents parallely ya sequentially bina conflict ke execute kar sakein.

### 5. 🧹 Simplicity & Extreme YAGNI (Anti-Overengineering)

#### `simplify` — Musk 5-Step Pruning & Srivatsaa Decision Mapping
* **Directory:** [`skills/simplify/`](./skills/simplify/SKILL.md)
* **Trigger:** `/simplify`, `/prune`, `/anti-overengineering`
* **Purpose:** *"Stop solving problems that don't exist."* Plans aur code se speculative abstractions, premature patterns aur defensive bloat ko delete karna.
* **Use Cases:**
  1. *Step 1: Make requirements less dumb* (Question who asked for it).
  2. *Step 2: Delete the part or process* (If you're not adding things back 10% of the time, you're not deleting enough).
  3. *Step 3: Simplify and optimize* (Never optimize something that should not exist).
  4. *Step 4: Accelerate cycle time.*
  5. *Step 5: Automate last.*

#### The `ponytail` Suite — Extreme YAGNI & Minimal Solutions
* **Directory:** [`skills/ponytail/`](./skills/ponytail/SKILL.md)
* **Components:**
  1. **`ponytail`** (`/ponytail`, "lazy mode"): Minimalist solution jo actually kaam kare — native platform features, stdlib over external packages, 1 line before 50 lines.
  2. **`ponytail-audit`** (`/ponytail-audit`): Poore repository ka audit — kya delete kiya ja sakta hai, kahan stdlib use ho sakti hai.
  3. **`ponytail-review`** (`/ponytail-review`): Git diff review focusing purely on cutting overengineering.
  4. **`ponytail-debt`** (`/ponytail-debt`): Codebase me chodi gayi deliberately deferred shortcuts (`ponytail:` comments) ka ledger report.
  5. **`ponytail-gain`** (`/ponytail-gain`): Compact scoreboard — kitni lines bachi, kitna bundle size kam hua, kitni speed badhi.
  6. **`ponytail-help`** (`/ponytail-help`): Quick cheat sheet.

## 🚀 Installation & Agent Setup

### 1. Google Antigravity (AGY) / Gemini CLI
Apne AGY skills directory me clone ya copy karein:
```bash
git clone https://github.com/meabhisheksoni/skill.git ~/.gemini/config/skills/suite
# Individual skills copy karein:
cp -r ~/.gemini/config/skills/suite/skills/* ~/.gemini/config/skills/
```

### 2. Claude Code
```bash
mkdir -p ~/.claude/skills
cp -r skills/* ~/.claude/skills/
```

### 3. Cursor / Windsurf
Apne project workspace ke `.cursor/rules/` ya `.windsurf/rules/` directory me required `SKILL.md` add karein.
